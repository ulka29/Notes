# Greedy Algorithms — GATE + UGC-NET Important Notes

## 1. Greedy Algorithm Fundamentals ⭐⭐⭐⭐⭐

### What is a Greedy Algorithm?

A **greedy algorithm** builds a solution step-by-step by making the **best local choice at every step**.

> **Greedy idea:** Choose the best available option now, without reconsidering previous choices.

### General structure

```text
Candidate Set
     ↓
Choose locally best candidate
     ↓
Feasibility Test
     ↓
Accept / Reject
     ↓
Repeat
```

### Important terms

| Term                    | Meaning                                              |
| ----------------------- | ---------------------------------------------------- |
| **Candidate set**       | Set of elements from which choices are made          |
| **Selection procedure** | Determines the best candidate to consider            |
| **Feasibility test**    | Checks whether adding candidate violates constraints |
| **Objective function**  | Quantity to maximize/minimize                        |
| **Feasible solution**   | A solution satisfying all constraints                |
| **Optimal solution**    | Best feasible solution                               |
| **Greedy choice**       | Locally best choice made at each step                |

### Example

Suppose you want to select the maximum number of non-overlapping activities.

A greedy strategy is:

> Select the activity that finishes earliest.

Why?

Because an activity that finishes early leaves maximum time for future activities.

---

# 2. Local Optimum vs Global Optimum ⭐⭐⭐⭐⭐

This distinction is **very important for GATE conceptual questions**.

### Local optimum

Best choice **at the current step**.

### Global optimum

Best solution **among all possible feasible solutions**.

A greedy algorithm assumes that making appropriate local choices will eventually produce the global optimum.

### Important warning

> **A locally optimal choice does NOT always produce a globally optimal solution.**

This is why greedy algorithms require a correctness argument.

---

# 3. Greedy Choice Property ⭐⭐⭐⭐⭐

### Definition

A problem has the **greedy-choice property** if:

> A globally optimal solution can be obtained by making a particular greedy choice first and then solving the remaining problem optimally.

In simple words:

**Can I safely make this choice now without worrying that I am destroying the optimal solution?**

If yes → greedy may work.

---

# 4. Optimal Substructure ⭐⭐⭐⭐⭐

A problem has **optimal substructure** if:

> An optimal solution to the entire problem contains optimal solutions to its subproblems.

### Example

Suppose the optimal solution contains some first choice.

After making that choice, the remaining portion should also be solved optimally.

---

## Greedy Choice Property vs Optimal Substructure

This is a **very common theory question**.

| Greedy Choice Property              | Optimal Substructure                      |
| ----------------------------------- | ----------------------------------------- |
| Concerns the **first choice**       | Concerns the **remaining subproblem**     |
| Choice can be made safely           | Remaining problem has an optimal solution |
| Characteristic of greedy algorithms | Also important in DP                      |
| Stronger/different idea             | Not sufficient alone for greedy           |

### Remember

> **Optimal substructure alone does NOT imply that greedy works.**

A problem may have optimal substructure but still require Dynamic Programming.

---

# 5. Why Can Greedy Algorithms Fail? ⭐⭐⭐⭐⭐

Greedy fails when the locally best choice can prevent the globally best solution.

### Example: 0/1 Knapsack

Suppose:

| Item | Value | Weight | Value/Weight |
| ---- | ----: | -----: | -----------: |
| A    |   100 |     20 |            5 |
| B    |    90 |     18 |            5 |
| C    |   120 |     30 |            4 |

If capacity and item combinations make the ratio-based choice incompatible with the optimal combination, simply choosing the highest ratio is not guaranteed to work.

Therefore:

> **Value/weight ratio is not a valid greedy rule for general 0/1 Knapsack.**

---

# 6. Greedy vs Dynamic Programming ⭐⭐⭐⭐⭐

This comparison is extremely important.

| Greedy                           | Dynamic Programming                                                             |
| -------------------------------- | ------------------------------------------------------------------------------- |
| Makes one choice at a time       | Considers multiple subproblem possibilities                                     |
| Choice is generally irreversible | Stores solutions of subproblems                                                 |
| Usually does not revisit choices | Reuses previously computed results                                              |
| Requires greedy-choice property  | Requires optimal substructure + overlapping subproblems in the usual DP setting |
| Often simpler                    | Usually more computation/memory                                                 |
| Example: Fractional Knapsack     | Example: 0/1 Knapsack                                                           |

### Most important examples

| Problem                            | Standard technique |
| ---------------------------------- | ------------------ |
| Activity Selection                 | **Greedy**         |
| Fractional Knapsack                | **Greedy**         |
| 0/1 Knapsack                       | **DP**             |
| Weighted Activity Selection        | **DP**             |
| Huffman Coding                     | **Greedy**         |
| Minimum Spanning Tree              | **Greedy**         |
| Dijkstra with non-negative weights | **Greedy**         |

# 7. Greedy Proof Techniques ⭐⭐⭐⭐⭐

For GATE, you generally need to **recognize the proof idea**, not write a highly formal mathematical proof.

---

## A. Exchange Argument ⭐⭐⭐⭐⭐

Very important.

### Basic idea

1. Take an optimal solution.
2. Look at the greedy choice.
3. Show that we can replace some choice in the optimal solution with the greedy choice.
4. The solution remains optimal.
5. Therefore, there exists an optimal solution containing the greedy choice.

### Commonly associated with

* Activity Selection
* Fractional Knapsack
* MST reasoning

### Exam language

If a question says:

> "Replace the first choice of an optimal solution with the greedy choice without decreasing the quality of the solution."

Think:

**Exchange argument.**

---

# 8. Greedy Stays Ahead ⭐⭐⭐⭐

Idea:

> After every step, the greedy solution is at least as good as the corresponding solution produced by another strategy.

You compare the progress of greedy against another possible solution.

### Exam clue

If the question says:

> "Show that after each iteration, greedy has performed at least as well as any competing solution."

Answer:

**Greedy stays ahead.**

---

# 9. Cut Property ⭐⭐⭐⭐⭐

Extremely important for **Minimum Spanning Tree (MST)**.

### Cut

A cut divides the vertices of a graph into two sets.

For example:

```text
        A A A | B B B
              ↑
            Cut
```

Edges connecting A to B are **crossing edges**.

### Cut Property

> A minimum-weight edge crossing a cut is safe to include in some MST.

This is the fundamental idea behind:

* **Kruskal's Algorithm**
* **Prim's Algorithm**

### Important trap

The statement is about the **minimum-weight edge crossing the cut**, not simply the globally minimum edge in the entire graph.

---

# 10. Activity Selection Problem ⭐⭐⭐⭐⭐

One of the most important greedy problems.

### Problem

Given activities:

[
(s_i,f_i)
]

where:

* (s_i) = starting time
* (f_i) = finishing time

Select the **maximum number of mutually compatible activities**.

### Compatible activities

Two activities are compatible if one finishes before the other starts.

Usually:

[
s_j \geq f_i
]

---

# 11. Activity Selection — Greedy Rule ⭐⭐⭐⭐⭐

> **Always choose the activity with the earliest finishing time.**

### Algorithm

```text
Sort activities by finish time

Select first activity

For each remaining activity:
    if start time >= finish time of last selected:
        select activity
```

### Why earliest finish?

Because it leaves the **maximum remaining time** for other activities.

---

# 12. Activity Selection Example

Suppose:

| Activity | Start | Finish |
| -------- | ----: | -----: |
| A        |     1 |      2 |
| B        |     3 |      4 |
| C        |     0 |      6 |
| D        |     5 |      7 |
| E        |     8 |      9 |

Sorted by finish time:

```text
A(1,2)
B(3,4)
C(0,6)
D(5,7)
E(8,9)
```

Select:

```text
A → B → D → E
```

Total:

[
\boxed{4}
]

---

# 13. Activity Selection Complexity ⭐⭐⭐⭐⭐

If activities are not sorted:

### Sorting

[
O(n\log n)
]

### Selection

[
O(n)
]

Therefore:

[
\boxed{O(n\log n)}
]

If activities are already sorted by finish time:

[
\boxed{O(n)}
]

### GATE trap

If a question asks:

> "Complexity after activities are already sorted by finish time?"

Answer:

[
\boxed{O(n)}
]

Not (O(n\log n)).

---

# 14. Activity Selection — Important Traps ⭐⭐⭐⭐⭐

### Maximum number of activities

→ Earliest finishing time.

### Maximum total profit/weight

→ **Weighted Activity Selection → DP**

### Maximum total duration

→ Not the standard activity-selection problem.

### Common wrong greedy strategies

These are **not generally correct** for maximum number of activities:

* Earliest starting time
* Shortest duration
* Latest starting time
* Maximum duration

Correct strategy:

[
\boxed{\text{Earliest finish time}}
]

---

# 15. Fractional Knapsack ⭐⭐⭐⭐⭐

Given:

* Item weight (w_i)
* Item value (v_i)
* Knapsack capacity (W)

You may take **fractions of an item**.

### Goal

Maximize:

[
\sum v_i
]

subject to:

[
\sum w_i \leq W
]

---

# 16. Fractional Knapsack — Greedy Rule ⭐⭐⭐⭐⭐

Calculate:

[
\boxed{\frac{v_i}{w_i}}
]

for every item.

Then:

> Sort items in decreasing order of value/weight ratio.

Take the highest-ratio item first.

If the entire item cannot fit:

> Take the required fraction.

---

# 17. Fractional Knapsack Example

Capacity:

[
W=50
]

| Item | Weight | Value | (v/w) |
| ---- | -----: | ----: | ----: |
| A    |     10 |    60 |     6 |
| B    |     20 |   100 |     5 |
| C    |     30 |   120 |     4 |

Order:

[
A \rightarrow B \rightarrow C
]

Take A:

[
10
]

Remaining capacity:

[
50-10=40
]

Take B:

[
20
]

Remaining:

[
20
]

C weighs 30, so take:

[
\frac{20}{30}
]

of C.

Value obtained:

[
60+100+\frac{20}{30}(120)
]

[
=60+100+80
]

[
\boxed{240}
]

---

# 18. Fractional vs 0/1 Knapsack ⭐⭐⭐⭐⭐

**Memorize this table.**

| Property                    | Fractional Knapsack | 0/1 Knapsack     |
| --------------------------- | ------------------- | ---------------- |
| Fraction allowed            | Yes                 | No               |
| Greedy ratio                | Works               | ❌ Not guaranteed |
| Standard technique          | Greedy              | DP               |
| Item can be partially taken | Yes                 | No               |
| Optimal substructure        | Yes                 | Yes              |
| Overlapping subproblems     | Not the main issue  | Important for DP |

### Golden rule

> **Fractional → Greedy**

> **0/1 → DP**

# 19. Huffman Coding ⭐⭐⭐⭐⭐

Huffman coding is another major greedy algorithm.

### Goal

Construct an **optimal prefix-free binary code**.

It is generally used for **lossless data compression**.

---

# 20. Prefix-Free Code

A code is prefix-free if:

> No codeword is a prefix of another codeword.

Example:

```text
A = 0
B = 10
C = 110
D = 111
```

This is prefix-free.

But:

```text
A = 0
B = 01
```

is **not** prefix-free because `0` is a prefix of `01`.

---

# 21. Huffman Greedy Rule ⭐⭐⭐⭐⭐

> Repeatedly combine the **two least frequent** symbols/nodes.

### Algorithm

```text
Insert all frequencies into min-heap

        ↓

Extract two minimum frequencies

        ↓

Combine them

        ↓

Insert combined frequency

        ↓

Repeat until one node remains
```

---

# 22. Huffman Example

Suppose frequencies are:

```text
A = 5
B = 9
C = 12
D = 13
E = 16
F = 45
```

First combine:

[
5+9=14
]

Now:

```text
12, 13, 14, 16, 45
```

Combine:

[
12+13=25
]

Then continue selecting the two smallest.

The final tree gives the Huffman codes.

### Important observation

High-frequency symbols generally get **shorter codes**.

Low-frequency symbols generally get **longer codes**.

---

# 23. Huffman Weighted Path Length ⭐⭐⭐⭐⭐

If symbol (i) has:

* frequency (f_i)
* code length (l_i)

Then:

[
\boxed{WPL=\sum f_i l_i}
]

or equivalently, when frequencies are actual probabilities:

[
\boxed{L=\sum p_i l_i}
]

### Exam use

Questions may give a Huffman tree and ask:

* Total weighted path length
* Average code length
* Which symbol gets shortest code
* Which tree is optimal
* Number of bits required

---

# 24. Huffman Coding Complexity ⭐⭐⭐⭐

Using a **min-heap**:

* Insert (n) elements
* Repeatedly extract two minimum elements
* Insert combined node

Overall:

[
\boxed{O(n\log n)}
]

### GATE trap

If the question specifically asks about the data structure used for efficient Huffman construction:

[
\boxed{\text{Min Heap / Priority Queue}}
]

# 32. Type 9 — Which Statement Is Correct?

These are common UGC-NET/GATE conceptual questions.

### Statement A

> Every optimization problem with optimal substructure can be solved using greedy.

❌ False.

### Statement B

> Greedy-choice property is important for proving correctness of greedy algorithms.

✅ True.

### Statement C

> Fractional Knapsack can be solved optimally using value/weight ratio.

✅ True.

### Statement D

> Value/weight ratio always solves 0/1 Knapsack.

❌ False.

**“Finish – Ratio – Minimum – Cut”**
